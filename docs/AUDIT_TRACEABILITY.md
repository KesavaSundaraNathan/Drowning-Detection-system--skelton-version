# Audit traceability

Every finding of the **2026-10-07 production-readiness audit** of the v2 tree (scored 3/10) is mapped here to its resolution in v3, with evidence: a test that fails if the fix regresses, a document, or a phase report.

- **The rows** come from the frozen copy of the audit's tables: [`docs/audit/PRODUCTION_AUDIT_2026-10-07.md`](audit/PRODUCTION_AUDIT_2026-10-07.md).
  - **C1–C10:** the ranked critical findings (§1.0).
  - **1.1-n to 1.7-n:** the per-file rows (§1.1–1.7), numbered in table order.
- **The CI gate** is `tools/check_traceability.py`, a step in `tools/ci.ps1`. It fails if:
  - an audit row is missing or duplicated, or its label differs from the audit's;
  - a row has no evidence;
  - any evidence reference does not resolve (the file must exist, and a named test or text must occur in it);
  - a **FIXED** row cites no test.
- **Evidence syntax:**
  - `path::name` names a test function (Python) or test title (TypeScript) in that file;
  - `path#text` names text that must occur in the file;
  - a bare `path` must exist.

| Status | Meaning |
|---|---|
| **FIXED** | Every required fix is done, and a test would fail if it regressed. |
| **MITIGATED** | The risk is controlled, but part of the required fix is not done. The row names that part. |
| **ACCEPTED** | The audit required no fix ("None critical" / "Works" / "Fine"); kept as is, with its tests. |
| **DROPPED** | The component is not in v3, and a test keeps it out. |
| **OPEN** | Needs something code cannot supply (data); the row says what. |

**Summary:** 81 rows. **51 FIXED, 11 MITIGATED, 8 ACCEPTED, 10 DROPPED, 1 OPEN.**
